# 输入、分类与路由

归类只拆分原文，不在清点阶段改写。为每项记录 ID、原文、类别、来源位置、事实状态。类别可以缺省：材料不需要行动步骤时记“不适用”；未提供的可选项记“未提供／不设置”，不为凑齐六类询问或创造信息；只有用户明确请求事项的必要字段缺失或冲突时记“待确认”并集中询问。

## 六类输入

服务对象（适用与资格）、服务事项（服务与主题）、时间地点（日期、时段、地址、点位）、行动步骤（申请/参加/求助）、注意事项（风险、条件、费用及否定）、图形素材（照片/图标/标识/授权）。一句含多项可拆分，用来源 ID 关联。事实表区分“用户提供、官方核实、待确认、示例”，用户提供不自动等于已核实。

## 信息骨架

S1 时间地点公告；S2 步骤流程；S3 清单条目；S4 分类对比；S5 警示禁止；S6 招募邀约；S7 数据公示；S8 空间导视；S9 求助联络。每项一个主骨架，辅助区可以借用其他结构。S7具备真实数据和周期/单位后可做；S8具备确认的地图和点位后可做，不是永久拒绝。

## 五轴记录

记录领域、信息功能、受众、时效、发布身份。受众编号见 audience-layout.md。时效写明常设/定期/限时/即时应急，并记录适用日期；发布身份写真实机构和依据，不因领域或收费推定“官方”。旧包 L 编号同时指权威、来源与共享层，修复版改为独立字段：authority（真实发布身份）、source_status（核验状态）、design_layer（设计层）。无法判定时注明未知，不制造等级；未提供发布机构则不设置落款，未提供日期则不虚构活动期限，也不触发固定补资料或用途问答。

路由可以存为 theme.json：theme_id、domain、function、audience、languages、timeliness、publisher、source_status、canvas、status。画布各值带单位；语言使用实际语言标识。JSON仅是可选记录格式，技能执行不依赖缺失的 taxonomy.yaml。
